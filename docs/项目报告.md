# 成分真言 · 项目报告（黑客松提交版）

> 第二届欧莱雅「有意思青年–科技大 Fun 颂」美妆科技黑客松 · 赛题二：信任守护师
> 2026-08（随开发进度持续更新）

## 一句话

**「成分真言」是一个敢说真话的化妆品功效核验系统：把功效剂量做成知识表示的一等公民，让每个结论都有证据、每个证据都可查证、每个不确定都明说。**

## 我们守护什么

赛题说「伪造背书」。图片可以 P，文献 P 不了。种草内容里最伤消费者钱包的不是假图，而是**那句无法溯源的功效宣称**——「这个成分能美白」。我们核验的就是这句话。

这不是概念问题，是有法规牙齿的真问题：《化妆品功效宣称评价规范》（药监局 2021 年第 50 号公告）强制要求功效宣称必须有评价依据并公示摘要；市监局对「宣称抗老无法提供依据」持续开罚单。美妆内容生态缺一个「文献级鉴伪官」。

## 系统做什么

用户丢来一篇种草文或一个产品名，系统在 30 秒内输出一份**可验证的核验报告**：

1. **成分问答**：对话式核验。每条功效结论句尾挂 [n] 引用编号，点击展开证据卡（真实论文，可跳 PubMed）。模型只许根据证据库回答——证据不足就明说「证据不足」。
2. **圆桌核验**：四位 AI 角色开圆桌——成分专家（产品库）、文献核验官（证据库）、剂量推断师（浓度引擎）、法规合规官（NMPA 宣称摘要库），各自绑定不同的工具与独占信息源，讨论过程全程可视，最终由裁决 Agent 输出**五级判定**：
   证据相悖 / 证据不足 / 证据支持但剂量无法判定 / 剂量达标但透皮存疑 / 证据支持但剂量存疑 / 与证据·剂量·透皮一致（估计）。
3. **真平替与每起效成本**：三级相似检索（成分集合→剂量级→功效级）找到相似产品，并算出「达到起效浓度的每日成本」——例如同样达到美白起效浓度，某爆款约 ¥0.4/天，某贵妇精华约 ¥30/天，相差约 78 倍。
4. **图像鉴伪**（赛题多模态要求）：AI 生图检测，守住「图片篡改」题面。

## 三个技术支点（为什么是新的）

### 1. 功效剂量一等公民

安全/毒理侧剂量早已被结构化，但**功效起效浓度从未被结构化进证据承载型知识表示**。我们把剂量贯穿到每一层：

- **知识库**：每条「成分→功效」断言挂起效浓度（真实文献）+ 证据层级（人体 RCT/开放试验/体外/动物/口服/复方，全部如实标注）
- **判定**：文献起效浓度 × 推断浓度区间 → 剂量达标判定（达标/存疑/不足/微量 ppm 级）
- **评测**：`verdict ∧ evidence ∧ dose` 三条件计分——据我们所知，第一个把剂量塞进核验指标的工作

### 2. 证据强制（evidence enforcement）

「每条断言必须挂真实文献」不是 prompt 要求，是**架构强制**：数据库层 NOT NULL + 外键约束（无证据、假证据都入不了库）+ 每条 paper 类证据入库前过机器核验（PMID → NCBI 标题比对，不一致即驳回）。60 篇文献全部经此闸门验证，弱证据（口服/动物/体外/复方）逐条如实标注——包括一条如实收录的**阴性结果 RCT**（5% 传明酸外用无效）。

### 3. 功效指纹

产品不止由成分组成，更由「能做什么」定义。我们把产品投影到功效空间：功效维度 ×（推断剂量 × 证据强度）加权，跨品牌找「成分不同但功效等价」的真平替（剂量达标硬约束），三级相似度全部标注置信口径。

## 数据资产（全部真实、可溯、合规）

| 资产 | 规模 | 来源 |
|---|---|---|
| 产品备案档案 | 130+ 品牌产品（每日自动扩采） | NMPA 备案公示（盖德镜像，Playwright 合规采集） |
| 功效宣称依据摘要 | 340+ 条结构化 | NMPA 法定公示内容 |
| 成分证据库 | 100 成分 / 190+ 断言 | PubMed 经典文献，机器核验 100% |
| 官方降序成分表 | 17 产品 + 13 披露锚点 | INCIDecoder/品牌官网人工核实 |
| 浓度推断引擎 | 约束采样（降序+0.1% 微量线+法定上限+Σ=100+剂型先验），锚点校准 | 自研，跨 seed×样本量 12 组合稳健 |
| 原料理化库 | 43 成分 CID 映射 | PubChem PUG-REST |

合规红线：不爬电商/美丽修行；采集礼貌延时 + 限流熔断；推断浓度全部标注「估计值」；价格/规格为人工采样并注明口径。

## 无幻觉是可量化的

自建 40 条域内评测集 + `verdict ∧ evidence ∧ dose` 三条件计分（本地 Qwen2.5-14B 实测）：

| 指标 | 分数 |
|---|---|
| E 引用正确率（挂对 PMID） | **97.5%** |
| V 判定正确率（含拒答） | **100%** |
| D 剂量措辞严谨度 | **77.5%** |
| 总分（三条件相乘） | **0.70** |

评测不是一次性的：第一轮发现剂量措辞只有 65%，改进 prompt + 在校验循环加「浓度数字强制限定语」规则后提升到 77.5%——**可测量、可改进、有数字**。

## 架构与部署

```
圆桌 Agent（四角色信息不对称分工，SSE 可视化）
  ├─ 模型层：Qwen2.5-14B（910B vLLM-Ascend 本地 ⇄ 云端 API 双通道）
  │    prompt RAG + schema 强制引用 → RARR 生成者-验证者循环（≤2 轮）
  ├─ 判定层：D1 语义 × D2 剂量 × D3 透皮（500Da/Potts-Guy+适用域闸）
  ├─ 表示层：BGE-M3 嵌入 + 功效指纹 + 三级相似索引（Faiss）
  └─ 数据层：证据强制知识库（SQLite→可切 PostgreSQL）+ 采集管线
全链路国产化算力：华为昇腾 910B（vllm-ascend + torch_npu）
```

工程纪律：432 项自动化测试全绿；每个模块经独立子代理审查迭代；推断浓度与判定输出全程带「估计」语义。

## 演示路径（决赛现场）

1. 评委丢一篇真实种草文 → 圆桌四 Agent 现场讨论（可视化）→ 30 秒出「断言-证据-剂量-透皮」报告
2. 点击引用编号 → 真跳 PubMed 原文
3. 每起效成本对比：同样达标，价格差 78 倍
4. 数字收尾：三条件计分跑分 + 锚点校准覆盖率
